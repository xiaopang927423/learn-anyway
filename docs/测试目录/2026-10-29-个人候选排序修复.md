# 2026-10-29 个人候选排序修复

输入法独立组件 0.6.2 / build 6020，桌面和扩展仍为 0.6.1。本包包含前次云候选读音修复。

## 根因和修复

1. 原排序先比较简拼和末音节是否完整，再比较同输入选择次数。`kaifa` 选过「开放」仍被默认的「开发」压住。现在保留精确命中和覆盖范围优先，将个人选择提前到简拼和末音节规则之前。
2. 命中很多时，原预选只看结构、全局次数及词频；低频的同输入偏好可能在计算个人选择前就被淘汰。现在廉价的同输入选择次数参与预选，语言模型得分仍只对保留项计算。
3. 排序后插入的自动整句可能再次占据首位。现在插入整句后稳定提升覆盖当前整个输入的个人选择；保留中英策略决定的前置英文，自定义短语和快捷候选仍沿用后续规则，辅码过滤不走此次提升。

没有新增学习文件、迁移或联网行为。沿用原有确认上屏后的累计选择记录、保存/重载和私密/学习开关；本次没有增加时间衰减，也不自动修改历史错误词条。

## 失败复现与新增回归

修复前，下表中默认末音节、自动整句及大量候选三项失败；分词项原本通过，用于保留兼容。新增回归使用内存词库，不调用真实模型。

| 场景 | 操作与结果 |
| --- | --- |
| 默认末音节规则 | `kaifa` 选「开放」，下次 `kaifa` / `kai'fa` 首选为「开放」 |
| 输入覆盖边界 | 上述偏好不使「开放」压过 `kaifazhe` 的「开发者」 |
| 分词兼容 | `xian` 选「西安」后继续首选「西安」 |
| 双拼与改选 | 小鹤 `kdf` 原首选「开放」，选「开发」后首选变为「开发」；输入键按 `kaif` 记忆，再选「开放」两次后恢复其首选 |
| 自动整句 | 词库含「你」「好」和低频「拟好」，`nihao` 原首选整句「你好」，确认「拟好」后首选变为「拟好」 |
| 大候选池 | 2100 个高全局次数竞争词中，同 `kf` 输入选过的低频「开放」仍进入候选并排第一 |
| 真实持久化 | 使用临时目录的 FrequencyLearner，经 stage_candidate / commit_staged / remember_confirmed_phrase 确认「开放」，落盘重载后仍首选；改选累计次数超过后，重载也保留新首选 |
| 学习边界 | 暂存预览不增加次数；关闭学习或私密模式下确认其他词不写新偏好，仍可读取原偏好 |

新增测试位于 `qingjian-core/src/engine/tests/personalization.rs` 和 `qingjian-learning/src/frequency_learner/tests.rs`。原有中英优先、撤销学习、纠错、辅码、自定义候选等回归也全部通过。

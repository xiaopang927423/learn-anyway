# 2026-10-29 人名记忆与拼音匹配修复

输入法独立组件 0.6.3 / build 6030，桌面和扩展保持 0.6.1。包含前次个人排序与云读音修复；使用构造人名，未读取用户私人人名或学习库。

## 已复现缺陷

- 分字确认「张」「宇」「萱」时，commit_staged 原先逐片段单独设置输入，提交看到的 buffer_left 总为假。同串拼音的整词记忆没有触发，完整姓名选择次数为 0；两次确认后仍不能作为个人词召回。
- 全拼选过「张宇萱」，换成 `zyx` 时只查该简拼自己的次数，已有全拼选择无效，低频姓名仍被「这一下」等候选压住。
- `jinan` 已有完整词「济南」，仍由解析器最优的 `jin an` 生成「金安」占据首选。随包真实词库与静态语言模型均可复现，不是云模型问题。

这三项先写失败回归，再修复。随包 `xian` 的候选也含「见」等生僻/多音读法，此次没有删除这些词条；它们需要词库层面的独立校订，不能据候选不常见就判为非法读音。

## 新增和扩展验证

| 场景 | 结果 |
| --- | --- |
| 分字确认人名 | 同一串 `zhangyuxuan` 分字确认两次后，完整词进入个人词库并靠前 |
| 跨拼法持久化 | 全拼、小鹤双拼 `vhyuxr`、简拼 `zyx` 分字确认后，真实 FrequencyLearner 落盘重载；全拼、带分隔拼音、`zyx`、`zhangyx` 均首选构造姓名 |
| 双拼整句确认 | 小鹤 `xkhe` 确认「星河」，记录 `xinghe`，不记录原始双拼字母；同次输入选择不重复累计 |
| 退格改选 | 简拼采用姓名后产生的完整读音偏好，删除重选其他姓名时一并撤回 |
| 原样草稿 | 空按键的原样片段不吞后续候选按键及剩余拼音 |
| 分音歧义 | `jinan` 首选「济南」，`jin'an` 按显式分音首选「金安」，已学偏好也不破坏该分隔 |
| 云片段合词 | 前次五类云读音持久化场景各重复三次，错误模型读音不经自动造词重新污染个人词库 |

沿用已有私密、学习关闭、预览不学、输入覆盖、中英优先、撤销及辅码等回归。用户已有的计数文件不迁移、不重写。

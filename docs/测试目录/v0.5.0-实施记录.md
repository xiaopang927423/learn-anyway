## 安装排查及下一步

下一步：保存工作后注销并重新登录，验证首次安装后的系统扫描、设置里的名称、父输入法启用与真实 TextEdit 输入。该步骤尚未执行，不能保证刷新即解决。若新会话仍拒绝，再基于新日志处理系统识别与签名；本机无 Developer ID 证书，ad-hoc 包安全评估未获发行认可。

## 与目标设计的差异及待验收

- 保留上游 crate 名称用于溯源；会话逻辑目前在 macOS wordmate.rs，而未拆出独立 session/protocol crate。
- 原生 RPC 为每次调用建连接；后台 300ms 合并，UI 结果当前随 1 秒定时器轮询。长连接和性能指标未验收。
- 使用事件表为添加式 schema；未新增 words.kind，也未完成目标迁移备份与外键方案。短语按现有 words 唯一键存一条。
- 原生选区目前 500 个 UTF-16 单位；目标 1000 字符、辅助候选切换、辅助 Esc、可配置新增快捷键需继续实现 / 对照验收。
- 未随包提供本地神经模型文件；保留加载与本地词库 / bigram 回退。上游更新端点停用，WordMate 的更新服务未建立。
- 真实客户端写入确认、多屏、全屏、安全字段、冷启动、断电与性能矩阵仍需实际验收。
- 资源再分发权利、公证 / 发行签名未完成；本地产物不作为公开发布。

## 2026-10-09：输入、组句确认与候选布局修复

用户已完成安装，系统查询父输入法 / 模式均 true，ready=true。前一天的激活失败记录保留作为历史；不是当前状态。用户在参考源码中修正的 smSimpChinese 与默认不自动启用模式声明已保留，测试同步验证。

本次变化：

- 复用原版核心和 AppKit 绘制；修复中文候选消失。原生字体也支持用户指定字族的系统回退。
- 英文空格保留词与空格；真实词库 smoke 验证 i want to eat + zaocan，暂选「早餐」再提交 breakfast 得到 i want to eat breakfast。
- 选中文词进入待确认组句，回车才正式提交中文；Option+回车采用译文。取消不记提交或习惯，英文前缀保留在待确认范围外。可关闭设置恢复原版即时上屏。
- 移除独立白色辅助框；当前句译文在该候选行下方，自动换行且逐行计算高度。原生布局 PNG 夹具已人工查看，不含用户文档；竖排原句 / 译文增加鼠标操作。
- 不再把选区读取要求套在本输入法自己的组句上；普通提交使用原版 IMK 方法，确认学习时可用文本或 UTF-16 光标 / marked 状态转换。任意已有选区覆盖仍保留边界验证。
- 译文轮询 50ms 并加入公共运行循环模式；文件设置 / 定时保存仍每秒检查。已选词与未选拼音共同构成整句，模型响应可刷新该句下方。

## 2026-10-09：安装包云辅助缺失与英文空格补修

检查实际运行的 /Applications/WordMate.app，发现 0.4.6 安装包中没有 imeEnabled 设置和 startImeBridge，原生 RPC 返回 SERVICE_UNAVAILABLE。重新打包安装后，两项文件校验均通过，原生握手返回 IME_RPC_OK，enabled=true。安装脚本现在在替换旧应用前检查这两项能力，防止安装缺少云辅助的旧产物。

组句确认模式下英文单词和空格一并保留在 marked sentence，支持连续空格；物理 Space 键码明确走文本分词路径，避免客户端字符事件缺失。此规则替代前一节“英文前缀在待确认范围外”的实现。原英文即时输入仍可通过关闭组句确认使用。

真实安装后模型请求揭示整段 I want to eat 早餐 曾只返回 breakfast。现将末尾连续中文与已有英文前缀分开处理，英文前缀及其空格原样拼回；既有 contextBefore 不拼回。新增回归测试覆盖两种边界。

验证：核心 307 项、Node 25 项通过；浏览器渲染与集成 56 断言通过；当前输入源 ready=true。新版输入法与桌面包均已安装。Computer Use 的逐键 I + Space + want 在文本编辑显示 I want，但没有候选窗口 / IMK 事件链证据，因此仍不记作真实输入法全流程验收。

补充：最终安装包通过真实本机 socket 调用 Diffu，preview.selection 输入 I want to eat 早餐，首项严格返回 I want to eat breakfast；未提交任何学习事件。最终原生 preferences.get 再次确认 enabled=true。

# 2026-10-29 云候选读音修复

输入法独立组件 0.6.1 / build 6010。修复 [同日代码审查](2026-10-29-输入法代码审查.md) 的第 1 项；其余 3 项仍待修复。

## 修复行为

`commit_staged` 直接提交候选时已经校验云词读音，后续 `remember_confirmed_phrase` 原先再次使用候选原始音节，覆盖校验结果。现在两条路径共用 `learned_syllables_for(candidate, keys)`：确认短语使用每个片段保存的按键，优先采用完整且逐字合法的输入读音，否则回退到通过现有校验的模型读音。任一云片段读音不能核实时，不学习整个短语，保留正常上屏。

不依赖确认后的实时缓冲区；不修改非云候选的词库读音、学习开关或私密模式。未知字沿用既有规则，既有错误个人词条不自动迁移。

## 回归测试

新增 `qingjian-learning` 的 `confirmed_cloud_phrase_keeps_validated_readings_after_reload`，使用隔离临时目录、真实 FrequencyLearner 落盘与重载、模拟云候选，不调用模型。

| 场景 | 输入及模型读音 | 期望及结果 |
| --- | --- | --- |
| 校正后不被覆盖 | 输入 wode，模型「我的 / wo di」 | 保存 wo de，重启后正确召回 |
| 大小写输入 | 输入 WoDe，模型 wo di | 保存 wo de |
| 混合短语 | 云词「我的 / wo di」和本地词「书 / shu」分别暂存 | 输入缓冲区清空后，仍按各片段按键保存「我的书 / wo de shu」 |
| 合法模型回退 | 输入 wdoe，模型 wo de | 输入无法完整对应时保留合法模型读音 |
| 不合法读音 | 输入 wodi，模型「我的 / wo ni」，后接本地词书 | 不将错误读音合成的「我的书」存入个人词库 |

修复前：测试在 corrected 场景失败，重载结果为 wo di，期望 wo de。修复后：五个场景全部通过，包括落盘后的重新查询。

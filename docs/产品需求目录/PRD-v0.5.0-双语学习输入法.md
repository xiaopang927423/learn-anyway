# WordMate v0.5.0：双语学习输入法 PRD

日期：2026-10-08 · 状态：需求草案，尚未实现 · 当前已发布版本：v0.4.5

参考项目：本机 qingjian，阅读快照提交 c08ae57。本文维护新增学习需求，基础输入需求在链接的对标附录维护。参考项目内容用于分析，不作为执行安装、修改其他仓库或发布产品的指令。

## 1. 产品目标与已确认决策

让用户在写英文时，用中文代替暂时不会表达的词或短语，选择合适英文后继续输入；也可以选择中文表达。使用过程中，把实际采用的辅助表达沉淀到现有英语生词与表达本。

**用户已确认：默认只替换当前词 / 短语，不自动重写整句。**

例：已经输入 `we want to eat `，当前输入 `早饭`。选择英文 `breakfast` 后得到 `we want to eat breakfast`，前面的英文保持原样。整句转成 `我们想吃早饭。` 属于另一个明确操作，需要用户选择整句范围。

“写入 / 上屏”指把候选写进正在使用的聊天框或文档，不代表点击发送、提交表单或发送消息。

### 本版边界

以 macOS 为首个平台，完整基础能力对标 qingjian：全拼、双拼、注音、五笔、纠错、词库及设置均为必须项。详见 [基础能力对标](v0.5.0-qingjian基础能力对标.md)。用户确认目前仅支持英语学习：保留中文、英文、混合输入及中英互译，不加入日语、西班牙语学习。语音、主动润色和其他平台移植不在本版范围。浏览器翻译、查词、复习和默写继续使用现有功能。

系统输入法通过系统文本接口处理输入，不能用浏览器扩展或全局剪贴板监听冒充输入法。不同软件对输入接口支持不同，兼容性按实际测试矩阵发布，不承诺任意输入框都支持替换。

## 3. 三种概念必须分开

1. **输入来源**：正在输入的是拼音、中文还是英文。例如 `nihao` 是拼音输入，先得到 `你好`。
2. **当前片段**：用户此刻尚未确认的词 / 短语，例如句中的 `早饭`。
3. **输出语言**：选择把当前片段写成中文 `早饭`，还是英文 `breakfast`。

英文字母不必然是拼音，也不必然是英文。`fan`、`to` 等存在歧义，候选必须让用户明确选择解释；不能只靠字符类型决定。

英文直输模式以保留原文为默认。混输模式可根据本地词表和拼音结果排序，但始终保留“原样输入”入口；用户能显式切到拼音解释或英文解释。

## 4. 补充输入场景

下列冒号是示例说明的分隔符，不定义特殊触发键。实际输入冒号、逗号等标点时，需要保留正常输入行为。

| 场景 | 输入 / 当前片段 | 可选中文 | 可选英文 | 默认处理与学习 |
| --- | --- | --- | --- | --- |
| 拼音问候 | `nihao` | 你好 | hello | 选择 hello 写入该词；不是输出字母 nihao 的机器翻译 |
| 拼音多候选 | `zaofan` | 早饭 / 早烦等本地候选 | breakfast（对应早饭） | 源中文含义改变后，英文候选随之更新 |
| 纯中文词 | `早餐` | 早餐 | breakfast | 采用英文可收录 breakfast，中文作为意思 |
| 中文短语 | `尽快` | 尽快 | as soon as possible | 收录表达，不拆成一串基础词 |
| 纯英文词 | `breakfast` | 早饭 / 早餐 | breakfast | 默认可保留英文；请求中文不自动证明该词不会 |
| 纯英文句 | `We want to eat breakfast.` | 我们想吃早饭。 | 原句 | 整句转换需要明确范围，不逐词自动收录 |
| 用户主场景 | `we want to eat [早饭]` | 早饭 | breakfast | 只改括号内片段，得到 `we want to eat breakfast`；收录 breakfast |
| 动词占位 | `Please [安排] a meeting.` | 安排 | schedule | 保留 Please 和 a meeting；收录 schedule |
| 名词占位 | `This is a good [机会].` | 机会 | opportunity | 收录 opportunity，不收录 this / is / good |
| 短语占位 | `Please reply [尽快].` | 尽快 | as soon as possible | 得到 `Please reply as soon as possible.` |
| 动作短语 | `We want to [吃早饭].` | 吃早饭 | have breakfast | 当前片段含动词，允许替换成 have breakfast |
| 语法位置限制 | `We want to eat [早饭].` | 早饭 | breakfast | 不把早饭翻成 have breakfast，避免 eat have breakfast |
| 多处占位 | `I will [安排] a meeting [明天].` | 安排 / 明天 | schedule / tomorrow | 分别确认两个片段，先前文字保持；学习事件分别记录 |
| 中文夹英文 | `我想使用这个 feature` | 功能 | feature | 活动片段为 feature；整句英译需另行选择范围 |
| 已知英文拼写 | `Please send me the report.` | 当前片段的中文候选 | 原英文 | 不因为能生成中文就改写原句或收录全部词 |
| 英文拼写错误 | `recieve` | 对应意思 | receive（拼写建议） | 建议明确标注，不能静默纠正；是否学习由用户决定 |
| 拼音歧义 | `xian` | 先 / 西安 | first / Xi'an | 先选源含义，不能给所有候选同一译词 |
| 拼音 / 英文歧义 | `fan` | 饭 / 风扇等 | rice / fan | 明确“拼音”与“英文”解释，原样候选保留 |
| 专名与技术词 | `Rust`、`CDL`、`gpt-6` | 必要时解释 | 原标识符 | 不翻成普通词，不自动当生词收录 |
| 地址 / 代码 | URL、邮箱、路径、代码 | 原样 | 原样 | 直输；默认不开实时云翻译 |
| 数字与日期 | `2026年10月8日 9:30` | 保留数字语义 | 用户显式转换的表达 | 不改时间数值、不把数字当候选快捷键误吞 |
| 句中修改 | `Please revise [这个文件] tomorrow.` | 这个文件 | this document | 只替换选择的片段，保留 tomorrow 及其位置 |
| 空格边界 | `eat[早饭]` | 早饭 | breakfast | 必要时加连接空格，得到 eat breakfast；不改 eat |
| 标点与 emoji | `我❤️[早饭]！` | 早饭 | breakfast | 字符范围正确，保留 emoji 和标点，不破坏文字位置 |

方括号只表示活动片段，不是要求用户输入的字符。例句中的英文不是唯一正确翻译，实际候选需结合语境。

## 5. 默认交互：边写边替换片段

### 5.1 主流程

1. 用户安装并在系统输入源选择 WordMate。
2. 输入已知英文时按普通英文写入；输入拼音时先显示本地中文候选。
3. 当前中文词 / 短语旁显示对应英文；已有本地或缓存结果即时展示，云结果稍后补充。
4. 用户选择中文或英文，结果只写入当前片段范围。
5. 成功写入英文后，学习收录在后台执行，不阻塞继续输入。

示意：

```text
聊天框：we want to eat [早饭]

当前片段：早饭
中文：早饭        [写入中文]
英文：breakfast   [写入英文]
语境意思：早饭；早餐
学习：采用英文后加入英语生词本（可关闭）

[原样输入] [整句转换…]
```

英文候选未准备好时，中文和原样输入仍可操作。云端到达不能自动选择、自动替换或改变用户已高亮的本地候选。

### 5.2 键盘与鼠标

基础候选编号及固定短语位置不被辅助结果占用；基础 Esc 清空组合串，翻译辅助 Esc 关闭译文回到基础组句。两种状态明确显示。

| 操作 | 需求行为 |
| --- | --- |
| 点击“写入英文 / 中文” | 确认当前对应候选；面板不抢走目标输入框焦点 |
| 空格 | 维持本地拼音选词 / 英文空格习惯，不默认强制接受云翻译 |
| 回车（基础组句中） | 保留原串上屏，不默认接受译文，不顺带发送聊天消息 |
| 原样输入 | 始终可用，保留用户字符；拼音歧义时能输出原字母 |
| 英文 / 中文候选快捷键 | 建议 Option+Enter / Option+Shift+Enter，仅活动候选期间生效；支持配置和冲突提示 |
| 方向、退格、删除 | 编辑当前片段，更新版本，取消旧结果的可写入资格 |
| Esc | 关闭翻译候选，不写译文；保留当前输入内容可继续编辑 / 原样确认 |
| 失焦、换输入框、切应用 | 隐藏旧候选并禁止迟到结果写入；不自动把译文插入新位置 |

快捷键为设计建议，必须在兼容性验证后定稿。系统切换输入源快捷键不被本输入法全局占用。输入法只负责写字，应用中的下一次回车 / 发送动作仍由用户决定。

### 5.3 空格、标点与替换范围

英语片段连接两侧英文单词时，按确定的邻接文字补必要空格，禁止出现 `eatbreakfast`。不默认在每个点击接受的词后添加空格；用户敲空格时保留该空格。中文词连接中文时不增加英文空格。

只替换活动片段或用户明确选区；不能读取到上文就擅自重写。前后已有标点与专名保留。应用不支持安全替换、选区改变或源文本不匹配时，不执行覆盖，显示可复制结果。

### 5.4 整句转换是明确的次级操作

用户点击“整句转换”并确认范围，才提供完整中文和英文候选。例如 `we want to eat 早饭` 可以转换为 `我们想吃早饭。` 或 `We want to eat breakfast.`。

整句范围只能是用户明确选区，或输入法仍可靠持有的当前组合句；没有可靠范围时，不猜测从当前聊天框取全文，改为复制结果。显示实际将替换的源句。整句转换不是写作扩展、自动补句或默认润色。

## 6. 实时性、请求与状态

- 拼音转换和普通输入在本机完成；网络不能阻塞按键处理和本地候选。
- 云翻译默认在用户首次开启输入辅助时说明发送范围；关闭后继续普通输入和可用本地译词。
- 300ms 输入停顿后请求，连续输入合并，不每个键请求一次。文字、源候选含义、当前片段或目标上下文改变都产生新版本。
- 请求包含会话、输入框、片段、源候选和版本标识；响应只对原标识组合有效。
- 目标输入框已改变、用户已确认 / 取消、内容变更或光标离开时，旧响应可丢弃，绝不能补写到下一处。
- 片段翻译采用独立的短期限：建议总计 5 秒，格式重试最多一次且共享期限。继承现有失败诊断，但不直接照搬网页 45 秒等待体验。
- 模型 / 地址 / Key / Thinking 复用 WordMate 现有设置；Thinking 默认关闭。开启 Thinking 也不延长输入阻塞时间。
- 词义优先本地词表 / 缓存，云端结合有限语境补充；缓存包括源词、语境、模型、目标语言与 Thinking。
- 后端冷启动或重启时异步恢复连接；本地输入立即可用，候选显示服务准备状态，不要求重启输入法或整台电脑。

状态序列：输入 → 本地候选 → 翻译中 → 当前有效双语候选 → 用户确认 → 写入成功 → 学习记录。确认、取消或失焦后不再接收该片段的写入操作。

## 7. 使用中学习与生词本

### 7.1 什么算“不会的词”

系统不能直接知道用户是否认识一个词。v0.5.0 使用可解释的信号：用户用中文占位，并实际采用对应英文表达。记录为“输入辅助待学表达”，不把模型自报置信度当作用户知识状态。

默认收录对象：

- 混合输入中，中文占位被用户替换成英文的词 / 短语。
- 纯中文 / 拼音词或短语中，用户主动选择英文输出的辅助表达。

已输入的其他英文、仅预览过的候选、取消结果、普通英文直输、自动拼写建议和整句翻译的全部单词，不自动收录。用户可主动点击任一可学习英文词“加入生词本”。

### 7.2 收录时机与规则

必须在目标应用写入成功后收录；预览或请求成功不能触发入本。自动入本需同时满足现有总开关和“输入辅助表达自动入本”开关，新开关建议默认开启。总开关关闭时，只保留手动加入。

- `早饭 → breakfast`：英语词条 breakfast，中文义“早饭 / 早餐”，上下文为实际采用后的英文语境，附原中文片段。
- `尽快 → as soon as possible`：表达条目一条；不把 as / soon / possible 全部当未知词。
- `安排会议 → schedule a meeting`：可收录完整表达；关键词 schedule 可建议手动选择，不自动拆满整句。
- 英语生词与表达使用现有本地学习库；中文是释义或占位来源，不新增中文母语生词库。本版仅英语学习词本。
- 重复采用同词更新使用记录，不重复建词，不把使用次数当查词次数，也不自动更改复习排程。
- 已掌握词保持已掌握；只有用户明确“重新学习”才能恢复学习状态。
- 采用词形记录原表面形式和可验证词元；无法可靠确认词元时先保留原形式，不猜造单词。

### 7.3 收录可靠性

每次确认有唯一 commitId；一次确认的写入和学习事件具有可追踪关联。重复回调 / 重连不重复上屏、不重复插入词条。词本临时不可用时，只重试学习记录，不重复写入文字；显示轻量“待保存 / 保存失败”状态，支持重试。

成功的已确认学习事件可形成有限本地待保存队列；不为未确认输入保存原始键盘日志。生词本展示来源“输入法”、使用次数、原中文意思和必要上下文。

## 8. 数据与隐私

- 本地拼音与候选不依赖云。首次开启云辅助须明确模型服务地址及将发送的文字范围。
- 原始拼音键串不必发送给云：本地先转换为用户选择的中文片段，再发送该片段及必要语境。
- 默认只使用本输入法在同一输入框内的近期文字作为语境；读取已有文字作为语境另设显式开关。建议上文最多 120 字符，可靠下文最多 80 字符，不传整个页面或聊天历史。
- 密码框、安全输入、被应用标记为私密的字段不缓存键串、不发送云请求、不收录生词。疑似 API Key / 私钥内容也应停止云处理，普通原样输入继续可用。
- 终端和代码编辑区域默认不启用云辅助，用户可按应用启用；邮箱 / URL / 路径 / 代码标识符不自动翻译或收录。
- 完整键盘日志默认关闭。参考项目的原文明文 debug 输入日志必须在适配时去掉或脱敏。
- 学习上下文只在确认收录后保存，建议最多 200 字符，用户可关闭上下文保存；API Key 留在桌面后端，不复制到输入法候选或导出文件。
- 取消请求不能撤回已经发送给服务商的数据，只停止后续发送、显示和写入。

## 9. 性能目标与容量

以下为待实现验收目标，不是已经测得的性能。

| 指标 | 目标 / 条件 |
| --- | --- |
| 本地按键到候选出现 | p95 ≤ 50ms，不等待网络 |
| 本地 / 缓存译词 | p95 ≤ 100ms |
| 云候选响应 | 约定网络与 Diffu、Thinking 关闭下，p50 ≤ 1.5s、p95 ≤ 3s；超时不阻塞普通输入 |

| --- | --- |
| TextEdit / Notes 原生文本区 | 拼音、混输、片段选择、中文 / 英文写入与恢复 |
| Chrome 标准 input / textarea | 不重复插入，不把确认候选当成表单提交 |
| Chrome contenteditable 编辑区 | 范围和光标准确，中文 / 英文输入可用 |
| 微信 macOS 聊天框 | 确认候选只写字不发消息；下一次发送由用户控制 |
| Typora 或常用文档编辑器 | 中间片段替换、标点、emoji、撤销和光标定位 |
| 终端 / 代码编辑器 | 默认原样输入，不拦截应用补全、命令和快捷键 |
| 密码 / 安全输入 | 无云请求、无学习记录、无原始输入日志 |
| 不支持可靠选区替换的应用 | 保留输入、显示复制结果，明确降级，不猜测写入位置 |

发布必须标明实测应用与版本。候选面板需要跨屏、全屏和 Space 切换验收；新安装 / 重启 / 退出桌面后端 / 输入法重新激活需要独立验收。

## 11. 参考项目的复用边界

qingjian 提供 macOS InputMethodKit 壳、本地候选与拼音引擎、非激活候选窗口、译词注记和选区翻译。其当前英文模式按空格确认词，中文组句也有自己的确认行为；不能直接沿用后便宣称完成 WordMate 的双语片段语义。

需要新增：

1. 任意位置的中英混合片段与明确源解释，解决参考项目部分混输仅识别句末英文的限制。
2. 当前片段中英输出选择、有限语境下的语法适配，不自动把已写英文重写。
3. 输入会话 / 版本 / 范围验证、防迟到写入、写入成功事件与词本幂等关联。
4. 复用 WordMate 模型和词本服务，而非维护第二套密钥及复习库。
5. 安全输入保护、取消明文输入日志，以及系统输入源和桌面后端的独立生命周期。

参考仓库声明 GPL-3.0-or-later，当前 WordMate 声明 MIT；实际复制 / 链接代码及打包词库之前，需建立许可与来源清单并确定使用方案。项目名与 logo 不默认复用；独立进程通信也不能被当作许可义务已解决的证明。本轮只完成需求和参考评估。

实现边界见 [输入法参考评估](../架构目录/v0.5.0-输入法参考评估.md)，验收用例见 [输入法验收计划](../测试目录/v0.5.0-输入法验收计划.md)。

## 12. 验收标准与实施关卡

### P0 发布验收

- `nihao` 可选择写入 你好 或 hello，拼音未被当作英文句子错误翻译。
- `we want to eat [早饭]` 默认只替换成 breakfast，前面英文逐字保持，不自动发送消息。
- 中文 / 英文输出与拼音 / 英文来源解释可明确区分；歧义可纠正。
- 已确认英文片段才收录；全局自动入本关闭、取消、仅预览、写入失败都不自动收录。
- 重复回调不重复写入和学习；词本失败不会导致第二次文字写入。
- 断网、后端重启、慢响应、原文改动、切输入框均不丢字、不误改。
- 密码和安全字段没有云请求、学习记录及原文日志。
- 兼容矩阵与重启流程真实测试，模拟接口不能替代系统输入源验收。

### 实施顺序

| 阶段 | 产物 | 通过条件 |

## 2026-10-09 交互修订：选字保留翻译机会

依据用户最新反馈，默认选中文字只转换为本输入法未确认的组句，不立即结束输入。用户可继续选择后续词，整句译文显示在对应候选句下一行。回车确认源句，Option+回车确认译文；取消丢弃未确认内容。独立白色辅助窗口移除。保留设置开关以恢复原版即时上屏。普通英文词与空格保留；i want to eat 后的早餐可以单独替换为 breakfast，既有英文不纳入改写范围。本条优先于早期“Space 立即基础提交”的描述。

实现决策：[ADR-004](../架构目录/ADR-004-选字与语言确认分离.md)；操作：[清单](../测试目录/v0.5.0-操作清单.md)。

### 英文空格补充验收（2026-10-09）

在默认待确认组句模式，逐键输入 I、空格、want、空格、to、空格、eat、空格必须保留为 I want to eat，不能连成 Iwant。连续空格保留。继续选择“早餐”后，采用英文得到 I want to eat breakfast；回车确认原文得到 I want to eat 早餐。待确认范围内的英文前缀属于结果，已提交的上下文不属于结果。云辅助不可用时本地输入和原文确认仍可使用。

# 开发与文档管理规范

## 目录与维护责任

项目维护者负责合并与发布；提交变更的人负责同步需求、架构和验证记录。每份文档只有一个维护位置；旧路径只能指向新位置。

- 产品行为、交互或范围变化：同步 `产品需求目录/PRD-WordMate.md` 和交互审查。
- 模块边界、存储、协议、权限或模型调用变化：同步 `架构目录/系统架构.md`；重大选择追加 ADR，说明原因与替代方案。
- 修复和新功能：同步 `测试目录/测试结果.md`，列命令、结果、执行日期、未验证项；必须区分模拟接口、真实模型请求和实际浏览器点击。
- 版本发布：更新 CHANGELOG，应用与扩展版本保持一致，并同步 package-lock。

## Git 工作流

本地仓库根为 English_study，默认分支为 main。当前已有代码与文档纳入版本管理；不自动创建远程仓库或推送。

后续功能使用 `feat/<简短名称>` 分支，修复使用 `fix/<简短名称>`，文档使用 `docs/<简短名称>`。提交标题采用 `feat:`、`fix:`、`docs:`、`test:` 或 `chore:`。变更包含代码、相关文档和必要验证，先提交到工作分支，经自查 / 人工评审后合并。

版本标签只在通过发布检查后创建。未通过真实浏览器验收的版本不能标记为已完成浏览器验收。回退使用 git revert，避免改写已共享历史。

## 必须执行的检查

在 wordmate 目录运行：

```sh
npm run lint
npm test
npm run test:browser
npm run test:host
npm run test:integration
npm run dist
```

纯文档变更可只运行 lint。模型行为变化还需受控真实模型请求；浏览器发布还需 Chrome / Edge 的手动安装、菜单点击和真实页面检查。自动化使用临时数据库，不导入真实模型密钥，也不修改日常学习库。

本仓库提供 macOS CI 配置；推送到 GitHub 后才由远程平台执行。仅有配置文件不代表 CI 已运行。

## 禁止提交与提交前检查

不提交 node_modules、打包应用、原生编译产物、SQLite 学习库、运行 socket、模型凭证、.env、本地日志和自动截图。测试截图可以作为本地证据，正式归档截图需确认不含密钥和私人页面内容。

仓库已配置 `.githooks/pre-commit`（core.hooksPath），提交时自动运行规范检查与暂存区凭证 / 产物扫描。新克隆仓库需运行 `git config core.hooksPath .githooks`。扫描是辅助保护，不能替代人工检查。

提交前查看 `git diff --cached` 和 `git status --short`；不要使用忽略检查强制添加凭证。依赖锁文件、测试源代码、架构和需求文档应提交。项目使用 npm lockfile 复现依赖。

## 发布与安装

验证通过后构建应用。运行 npm run install:mac：优先更新已存在的 /Applications/WordMate.app，否则使用 ~/Applications；保留旧应用备份，同步本项目已有用户目录副本，注册确切路径并更新本机连接配置；扩展需在浏览器中重新加载。学习数据保存在 Application Support，升级不覆盖学习库。

## 原生输入法独立版本管理

0.6.0 起输入法独立版本记录在 native Cargo 包、Info.plist、构建/打包/安装脚本；未修改桌面或浏览器时不提升其版本。原生功能变更运行相关 Rust 测试、隔离控制器回归、bundle 构建与安装状态检查、项目 lint；仅涉及原生时不重复无关浏览器/桌面打包。正式稳定发布仍须实际宿主验收。

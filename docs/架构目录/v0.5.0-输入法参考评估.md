## 建议组件边界

- 原生输入法壳：本地按键、拼音与候选、当前组合文字、光标、目标客户端和系统写入结果；不能依赖云响应处理普通按键。
- 输入会话服务：片段识别、源解释、版本号与替换计划。应用 / 输入框改变即使请求仍在执行，也失去写入资格。
- WordMate 桌面后端：模型配置、翻译调度、缓存、词义补充、生词库和复习。输入法不持有另一套 API Key。
- 学习事件：只有确认写入后产生，commitId 幂等；收录失败仅重试学习，不重放输入。

现有浏览器 page / selection RPC 与输入法服务需求不同，尤其是优先级、5 秒期限、客户端身份和确认事件。实施时新增输入法协议，不直接借用会自动入本的 lookup 作为候选预览。

macOS NSRange 与 Rust / JavaScript 的字符表示需要显式转换；emoji、多字节中文、组合字符必须测试，不能用字节下标直接替换。

## 复用与发布关卡

参考仓库声明 GPL-3.0-or-later，WordMate 当前为 MIT；先形成代码、词库、模型数据和品牌资产来源清单，确定许可方案，再复制或链接模块。本 PRD 不决定许可兼容结论，也不把分进程设计当作许可结论。

输入法与桌面应用采用独立组件身份：输入源安装于系统输入法规定的位置，后端沿用实际安装路径；升级不形成旧 / 新后端混用。第一版先验证本机 macOS 与目标应用，其他平台留到后续计划。

平台依据：[Apple marked text](https://developer.apple.com/documentation/appkit/nstextinputclient/setmarkedtext%28_%3Aselectedrange%3Areplacementrange%3A%29)、[replacementRange](https://developer.apple.com/documentation/inputmethodkit/imkinputcontroller/replacementrange%28%29?language=objc)。这些接口说明支持组合文字 / 指定范围，不证明所有第三方应用都能可靠替换。

# ADR-003：输入法本地核心与 WordMate 学习服务分离

日期：2026-10-08 · 状态：设计选定，待实施及 G0 验证

## 问题

输入法需要在任何按键下稳定完成本地组合；Electron / 云服务可能尚未启动。现有 translator.lookup 会计查词次数并可能自动入本，不适合候选预览。系统文本写入与词本数据库没有共同事务，重试处理不当会重复打字。

## 决策

采用 Rust 本地核心和 macOS IMK 适配，独立运行普通输入；Electron 统一模型配置和英语词本，通过单独 ime.sock / RPC v1 提供无副作用预览及 learning.commit。基础候选编号保留，片段辅助独立展示。可靠成功写入后才发送学习事件，commitId 事务去重；重连仅恢复预览 / 学习，不重放目标文本写入。不可靠提交降级人工检查，不虚构端到端恰好一次。

同用户私有 socket、握手凭证和版本协商限制接口；API Key 留在后端。仅英语学习，中文输入及中英输出保留。代码 / 数据复用的许可判断独立于进程划分。

## 替代方案与代价

把引擎放进 Electron 会让后端生命周期影响基础输入，且增加系统按键与 JS 主线程耦合，未采用。浏览器扩展 / 剪贴板方案无法覆盖原生输入法，未采用。原生输入法直接请求云与写词本会重复维护密钥和数据库，未采用。独立组件增加协议、安装和签名管理成本，因此必须通过 G0 原型及 G4 真实部署验证。

完整协议、状态和数据设计见 [v0.5.0 输入法架构](v0.5.0-输入法架构设计.md)；此 ADR 不意味着接口已实现或许可已解决。

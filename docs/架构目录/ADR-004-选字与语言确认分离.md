# ADR-004：选字与最终语言确认分离

2026-10-09 · 开发实现。

用户反馈：选中文字立即上屏会丢失整句翻译机会；英文前缀应保留，中文片段可替换为英文；译文应在对应候选句下方，不使用独立浮窗。

沿用 Qingjian 原版解析、词图、候选、纠错、习惯和原生 AppKit 提交接口。新增本机待确认组句：已选词和消费的键保存在原生 DraftWord 列表，未选拼音仍归原引擎。选择只调用 stage_candidate 消耗拼音，不计提交、不更新习惯；最终确认通过 commit_staged 记录原选词并只统计实际输出一次。输入框内使用 marked text，已上屏英文不纳入草稿范围。

默认开启 sentence_confirmation：空格 / 数字 / 点击原句先选词，回车确认源句，Option+回车或点击译文确认翻译；Shift+Option+回车也确认源句。开关位于输入法设置的通用页，关闭可恢复原版即时选词上屏；已有草稿仍等本次确认，不因修改开关丢失。显式 Control+Option+T 可重新翻译当前组句，或翻译客户端提供的已有选区。

整句模型预览、上下文与词本继续由 WordMate 后端处理。预览不入本；确认英文输出后，文本回验或当前 marked text 的结束 / 光标转换确认才允许学习。无法回读全文的客户端使用本输入法已知的组句光标和 UTF-16 偏移验证；普通组句提交沿用 insertText/replacementRange=NSNotFound，不因无法读文本而拦截输入。已有选区覆盖仍验证原范围和源文字。

候选窗口 Row 增加 assistant_translation，采用 AppKit 原生字体回退、按行高度和换行布局。独立辅助 NSPanel 已移除。当前选中句的译文画在它下一行；竖排原句与译文支持鼠标选择 / 采用，横排仍支持键盘确认。

自动英文空格识别只对合适的全拼英文 token / 英文语境起作用；完整拼音继续进入中文选词，Caps Lock 的明确英文模式保留。首词 i 及 i want to eat 早餐 的流程已由真实词库与模型验证。词元或词义对应不明确时不把整句拆成猜测的生词。

取舍：比原版增加了未确认组句状态。它必须在取消、安全输入时清理；失焦按标准 IMK 结束组句规则处理。客户端确认仍不是跨应用和 SQLite 的原子事务，不重放文字写入。实际应用、鼠标命中和混输兼容性需要继续逐项验收。

### 英文空格与混输范围补充（2026-10-09）

默认组句确认下，英文词边界也加入 DraftWord，text 包含原有大小写及尾随空格；候选查询不能删掉这些空格。物理 Space 明确分发，即使客户端没有 characters 也能处理。确认后统一提交整个 marked sentence。关闭组句确认则保留即时英文输出。

sourceText 中英文前缀属于待确认内容，与已提交的 contextBefore 不同。对末尾连续中文的混输，模型仅翻译中文，程序将英文前缀原样拼回，避免只输出 breakfast 后丢失 I want to eat。安装时校验后端入口和设置字段，版本号不能代替组件能力校验。
